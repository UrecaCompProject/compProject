# QA 리포트 (2026-09-01)

Playwright로 앱을 직접 띄워 기능별 골든 패스를 실행하며 테스트했다. 실제 원격 Supabase
프로젝트(`.env.local`의 dev 프로젝트)와 실제 `ai-consult` Edge Function(OpenAI)을 그대로
사용했고, seed.sql 계정이 원격 DB에는 없어 QA용 신규 계정을 자동 가입 플로우로 여러 개
직접 만들어 로그인 플로우까지 검증했다.

> **참고**: 이 QA를 진행하던 중 같은 작업 디렉터리에서 별도 Claude Code 세션이 동시에
> `getCurrentPlan.ts`(`.single()` → `.maybeSingle()`)와 리포트 생성 확인 모달
> (`ReportGenerateConfirmModal`)을 수정하고 있는 것을 발견했다. 아래 #5, #6은 그 작업과
> 겹치는 내용이라 "이미 진행 중"으로 표시해뒀다. 이 문서는 그 변경들이 커밋되기 전 시점
> 기준이다.

## P0 — 핵심 기능

### 1. "기타 상담"(general 모드)이 사실상 아무 질문에도 답하지 않는다

**재현**: 로그인 후 "기타 상담"을 누르고, 이어서 "해외 로밍도 되나요", "위약금 없이
해지할 수 있나요" 처럼 서로 다른 질문을 연달아 보내면 **매번 완전히 동일한 문구**가
돌아온다 —

> "어떤 도움이 필요하신가요? 요금제, 가입, 혜택 등 궁금한 내용을 자유롭게 입력해 주세요."

**원인**: [`supabase/functions/_shared/ai/recommend.ts:748`](../../supabase/functions/_shared/ai/recommend.ts#L748)의
`buildGeneralResponse()`가 OpenAI를 전혀 호출하지 않고 고정 문자열만 반환한다. 게다가
모드 라우터 [`resolveNextMode`](../../supabase/functions/_shared/ai/recommend.ts#L531)는
정규식 키워드(`추천/비교/가입/상담/문의/질문/도움/게임/출석/레포트`)로만 모드를 판별하고,
어느 것도 매치되지 않으면 `return current`로 이전 모드를 그대로 유지한다. 즉 한 번
"기타 상담"으로 general 모드에 들어가면, 이후 질문에 저 키워드가 우연히 포함되지 않는 한
영원히 이 고정 응답만 반복된다.

**영향**: "기타 상담"은 비로그인 사용자에게도 웰컴 화면 4개 퀵 리플라이 중 하나로 항상
노출되는 진입점이다(README의 서비스 소개 문구 "AI 챗봇이 분석하여 나에게 맞는 통신 요금제를
추천"과 정면으로 배치). 정형 플로우(추천/비교/가입) 밖의 자유 질문에는 사실상 아무 답도
못 하는 셈이라, 상담 리포트의 Q&A 요약도 모든 답변이 "어떤 도움이 필요하신가요?"로
채워지는 부작용까지 이어진다(실제 생성해 확인함).

**회귀 테스트**: `e2e/03-general-consult.spec.ts` (`test.fail`로 표시 — 고쳐지면
`test.fail`을 제거해서 정상 테스트로 전환할 것)

### 2. React Error Boundary가 프로젝트 전체에 하나도 없다

전체 코드베이스에 `ErrorBoundary`/`componentDidCatch`/`getDerivedStateFromError`가
전혀 없다(grep 결과 0건). 라우터도 없는 완전한 단일 페이지 구조라 모든 기능(채팅, 요금제,
리워드, 마이페이지 전부)이 하나의 React 루트에 물려 있다.

**직접 재현**: QA 도중 `ChatLoadingIndicator.tsx`가 `React.lazy`로 동적 로드하는
Lottie 청크(`@lottiefiles/react-lottie-player`)가 로드에 실패하는 상황을 두 번
관찰했는데, 두 번 다 화면 전체가 완전한 백지로 렌더링됐다(콘솔에 "Consider adding an
error boundary to your tree" 경고 동반). `Suspense`는 pending 상태만 처리할 뿐 reject된
Promise는 못 잡기 때문에, 지연 로드 청크 하나가 실패하면 앱 전체가 죽는다. 이번엔
Vite dev 서버의 의존성 재최적화(deps re-optimization) 타이밍과 맞물려 발생했지만,
운영 환경에서도 CDN 지연·광고 차단기·네트워크 순단 등으로 동일 청크가 실패할 수 있고,
그 순간 안전망이 전혀 없다는 구조적 공백 자체가 문제다.

**권장**: 최소한 앱 루트(`App.tsx`) 또는 `ChatPage` 레벨에 Error Boundary 하나를 두고,
`ChatLoadingIndicator`의 `Player` lazy import 실패는 로딩 인디케이터만 조용히 대체
UI(예: 점 3개 pulse)로 폴백하도록 감싸는 게 우선순위가 높다.

## P1 — 스펙/인프라 공백

### 3. README가 명시한 접근성 기능이 코드에 전혀 없다

README "주요 기능" 08번 항목: **"쉬운 모드 · 큰 글씨 모드 · 시니어 친화 UI"**. 코드베이스
전체를 `easyMode`/`fontSize`/`accessib`/`senior`/`큰글씨`/`쉬운모드` 등으로 검색했지만
관련 상태·컴포넌트·설정이 전혀 없다. 스펙 문서와 실제 구현 사이 괴리가 크다 — 실제
착수 전이라면 README에서 "구현 예정"으로 명시하거나 우선순위 표를 갱신하는 게 좋겠다.

### 4. 원격 dev DB에 QA/스테이징 테스트 계정이 없다

`supabase/seed.sql`에 `user1@example.com` / `user2@example.com`(비밀번호 `password`)
테스트 계정이 정의돼 있지만, 이건 로컬 `supabase start` + `db reset` 환경에만 적용되는
것으로 보인다. `.env.local`이 가리키는 원격 프로젝트로 실제 로그인을 시도하면
`Invalid login credentials`가 뜬다. 로그인이 필요한 기능(마이페이지, 리워드, 게임,
요금제 가입 등)을 사람이 QA하거나 이번처럼 E2E를 돌리려면 매번 실제 회원가입 플로우로
새 계정을 만들어야 한다 — Supabase Auth 가입 자체가 실제 프로덕션 성격의 프로젝트에
계정을 쌓는 셈이라 번거롭고, 정리(cleanup) 수단도 없다. 원격 dev 프로젝트에도 seed를
적용하거나, 최소한 팀이 공유하는 QA 계정 하나를 문서화해두는 걸 권장한다.

## P2 — 품질/UX

### 5. (진행 중으로 보임) `current_plans` 조회가 매번 콘솔에 406 에러를 남김

`getCurrentPlanRow()`가 `.select(...).single()`을 쓰는데, PostgREST는 매칭되는 행이
0개일 때 `.single()`에 대해 HTTP 406으로 응답한다. 코드가 `error.code === 'PGRST116'`
분기로 그 자체는 정상 처리하지만(요금제 없는 사용자는 그냥 `null`), 브라우저 콘솔에는
매번 406 에러가 두 번(마이페이지 진입 시 등) 찍혀 지저분하다. **QA 도중 다른 세션이
`.single()` → `.maybeSingle()`로 이미 고치는 걸 확인했다** — 그 변경이 맞는 방향이다.

### 6. (진행 중으로 보임) 상담 리포트 생성이 확인 없이 채팅을 초기화함

`useChatReport.handleGenerateReport`는 성공 시 `resetChat()`을 호출해 화면의 대화
내역을 웰컴 메시지로 되돌린다(저장 자체는 DB에 되므로 데이터 유실은 아니지만, 사용자
입장에선 방금까지의 대화가 갑자기 사라지는 것처럼 보인다). 사전 확인 다이얼로그가 없었다.
**QA 도중 다른 세션이 `ReportGenerateConfirmModal`을 추가해 리포트 생성 전 확인
단계를 넣는 작업을 하고 있는 걸 확인했다** — 정확히 이 문제를 겨냥한 수정으로 보인다.

### 7. 요금제 가입 완료 화면이 "신규 가입"인데 "요금제 변경"으로 표시된 사례 관찰

`e2e/02-signup-and-subscribe.spec.ts`로 **완전히 새로 만든 계정 하나로 처음부터
끝까지** 가입 플로우를 실행했을 때: "가입 유형" 단계에서는 정확히 **"신규 가입"**이
표시됐지만(`hasCurrentPlan`이 그 시점엔 `false`), 배송/약관 단계를 거쳐 "신청 완료"를
누른 직후 완료 화면은 **"요금제 변경이 완료되었어요"**로 바뀌어 있었다. 같은 플로우
안에서 `hasCurrentPlan`([`PlanSubscriptionSheet.tsx:274`](../../src/features/plan-subscription/ui/PlanSubscriptionSheet.tsx#L274))이
'confirm' 단계 렌더링 시점과 'agreement' 단계 제출 시점 사이 어느 순간 `false`→`true`로
바뀐 것으로 보이는데, 정확한 원인은 특정하지 못했다(같은 데이터를 읽는 경로가
`useCurrentPlan`(React Query, `PlanSubscriptionSheet`가 사용)과 `useSubscriptionStore`
(Zustand, `useChat`이 사용)로 두 군데 나뉘어 있다는 점은 확인함 —
[`useSubscriptionStore.ts`](../../src/features/plan-subscription/model/useSubscriptionStore.ts)).
DB에 저장되는 `current_plan_id` 자체는 항상 `null`로 넘어가 데이터 정합성 훼손까지는
아니지만, 사용자에게 잘못된 확인 메시지를 보여주는 건 명백한 버그다.
`e2e/02-signup-and-subscribe.spec.ts`를 그대로 재실행하면 재현되는지 확인할 수 있다
(다만 이번 QA 도중엔 동시에 다른 세션이 관련 파일을 수정 중이라 재실행 결과가 흔들릴 수
있었다 — 안정된 상태에서 한 번 더 돌려보는 걸 권장).

## P3 — 사소함

### 8. 배송 단계 "도로명 검색" 버튼이 항상 비활성화된 스텁

`PlanSubscriptionSheet.tsx:621-629`의 "도로명 검색" 버튼은 `disabled` 고정이라 클릭이
안 된다. 주소를 전부 수동 입력해야 한다 — 실제 주소 검색 API 연동 전 임시 상태로 보인다.

### 9. `Footer` 컴포넌트가 어디서도 쓰이지 않는 죽은 코드

`src/widgets/layout/Footer.tsx`는 `index.ts`에서 export되지만 `Layout.tsx`/`App.tsx`
어디에도 import되지 않는다. 라우터가 삭제된 리팩터링 과정에서 같이 정리되지 않은 걸로
보인다. 참고로 이 컴포넌트 안의 `<a href="/terms">`, `<a href="/privacy">`도 지금은
라우팅이 없어 실제로 붙이더라도 새 페이지 요청이 그대로 404가 될 것이다.

### 10. 채팅 입력창의 햄버거 메뉴 버튼에 `aria-label`이 없음

`ChatInput.tsx`의 메뉴 토글 버튼(`<Menu size={20} />`)은 다른 아이콘 버튼들
(`aria-label="메시지 전송"`, `aria-label="응답 생성 중지"` 등)과 달리 접근성 라벨이 없다.
스크린 리더 사용자는 이 버튼이 무엇인지 알 수 없다.

## 잘 동작한 것들 (회귀 위험 낮음)

실사용 계정으로 끝까지 확인한 것들 — 언급 없는 한 별문제 없었다.

- 회원가입 전체 플로우(기본정보 → mock OTP → 계정정보 → 약관 → 완료 → 자동 로그인)
- 로그인/로그아웃, 잘못된 자격증명 에러 처리
- AI 요금제 추천(폼 제출 → 실제 LLM 추천 3개, 사유·절감액 포함)
- 요금제 비교하기(전체 카탈로그에서 선택 플로우)
- 요금제 가입 5단계 마법사(요금 → 유형 → 배송 → 약관 → 완료), eSIM/USIM 분기
- 마이페이지(가입 정보, 사용량, 데이터/통화/문자 상세)
- 리워드 홈, 출석 룰렛, 배지 미션 목록, 배지 상점, 쿠폰함(빈 상태 포함)
- 게임 목록, 반응속도 게임 인트로, OX 퀴즈 3문항 전체 흐름 + 배지 획득 모달
- 상담 리포트 생성 → 저장 → 리포트함에서 조회
- 비로그인 사용자의 퀵 리플라이/입력창 잠금(로그인 유도) 정책

```
e2e/01-smoke.spec.ts               게스트 웰컴 화면, 로그인 실패, 입력창 잠금
e2e/02-signup-and-subscribe.spec.ts 회원가입 → AI 추천 → 요금제 가입 골든 패스
e2e/03-general-consult.spec.ts      "기타 상담" 버그 재현(test.fail, 고쳐지면 통과로 전환)
```

```bash
npx playwright test              # 전체 실행 (01 → 02 → 03 순서로 세션 재사용)
npx playwright test e2e/01-smoke.spec.ts   # 게스트 플로우만
```

**주의**:

- `02`, `03`은 실제 Supabase 프로젝트에 계정을 만들고 실제 OpenAI 비용이 발생한다.
  CI에 그대로 넣기보다는 로컬/수동 실행용으로 두거나, 백엔드 mock 계층이 생기면 그쪽으로
  옮기는 걸 권장.
- `03`은 `02`가 저장한 로그인 세션(`e2e/.auth/qa-user.json`, gitignore됨)을 재사용하므로
  파일명 접두 번호로 실행 순서를 보장해야 한다. `02`가 회원가입 단계까지만 성공하고
  이후(예: #7 버그)에서 실패해도 세션은 그 시점에 이미 저장해두게 만들어놨다.
- 이 프로젝트엔 지금 백엔드를 모킹할 방법이 없다(Supabase도, OpenAI도 전부 실호출) —
  이 자체도 "빠른/저비용 CI E2E"를 어렵게 만드는 인프라 공백으로 볼 수 있다.
